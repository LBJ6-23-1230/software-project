# 课程要求与初版定位

版本：0.1.0 初版。依据为用户提供的《课程项目说明.pdf》、两张老师课堂照片及四人分工确认。以下为要求摘要，原始课件未随代码上传。

## 老师的基本要求

- 团队最多 4 人。本组选题为校园失物招领系统。
- 每位成员至少完成两个独立功能的需求分析、设计、编码与测试，每个功能至少两项质量要求。
- 任务表含功能编号、功能名称、功能描述、验收标准、负责人、集成关系、接口契约、状态；功能编号唯一，每位成员至少两行。
- 团队至少两条非“无”的集成关系，可标注依赖、提供、联动、共用。
- 按课程实验完成验收及报告，真实记录个人贡献；期末另有尚未明确的专项任务。
- 课堂第二张图的商品、卖家、goods 接口是任务填写示例，不是本项目业务。

## 初版边界

该版本用于本机运行、演示流程、固定接口与后续分工开发。真实校园认证、即时通信升级、大模型匹配、定时备份和部署加固留待后续。每项质量目标的全部边界、性能指标及教师验收须另行完成，不能把自动测试通过等同于课程验收或个人贡献完成。

当前实现接口以 `shared/types.ts`、`docs/api-contract.md` 为准；历史需求草案或未来视觉方案不覆盖它们。最初采用 React + TypeScript / Express / SQLite 是本轮初版的实现选择，不是老师限定技术栈。
