## 2. 设计与实现说明

### F10

- `GET /api/admin/items` 以及 `POST /api/admin/items/:id/review` 的管理员响应现在额外包含 `reviewReason`；这个字段**仅在管理员端路由投影中添加**，不修改对外公开物品接口或共享 `Item` 类型。
- 后台审核页面在筛选不同审核状态时仍用全量管理员列表计算“待审数量”，避免把当前筛选结果误认为总待审数。
- 管理员可重新通过已驳回但仍 `active` 的记录；无法审核已撤回或已完成的记录。驳回原因只对管理员显示。
- 已有的 `hasActiveClaims` 下架保护和审查状态与物品生命周期隔离继续保留。

### F11

- `UPDATE disputes ... WHERE status='open'` 与变更行数校验保证只能从 `open` 转到 `resolved` 一次，已有结论不能被后续覆盖。
- 争议处理仅写 `disputes`，不直接更新 `claims` 或 `items`。争议提交仍由其他成员负责的路由承载，未擅改。

### F12

- 维持 `VACUUM INTO` 创建备份、SQLite 完整性与业务关联验证、显式 `confirm=true`、事务式恢复等既有逻辑。
- 恢复保留会话时，只保留 **用户在恢复前后都存在且密码摘要和角色未改变** 的会话。新用户或凭据/角色与恢复点不一致的旧会话会失效，需重新登录。
- 实际生产系统应进一步加入运维审计、异地备份、密钥管理及灾备演练；本项目不声称已实现自动备份或生产级恢复。

## 4. Windows 本地补验步骤

在拥有原仓库完整工作区、Node 24+ 与联网 npm 环境的 PowerShell 中：

```powershell
node -v
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

浏览器访问 `http://127.0.0.1:5173`，使用演示管理员账号登录。手工确认：

1. F10：待审条目审核通过后公开可见；驳回后公开入口不可见；管理员“未通过”列表显示驳回理由，且可重新通过。
2. F10：切换筛选条件后待审统计保持正确；进行中认领无法直接下架；非管理员访问管理接口被拒。
3. F11：认领参与人提交争议，管理员记录结论；重复处理失败；已完成认领终态不变。
4. F12：只对**新建的本地测试库**进行备份→修改测试数据→明确确认恢复；验证数据回滚和旧会话是否按凭据差异失效。
5. F12：用隔离备份副本模拟损坏/业务关系错误，确认返回错误且原数据不变。**不要在真实校园数据上做破坏性恢复测试。**
