# 拾光校园初版设计

用户目标：在已确定四人子系统分工的基础上先做可运行初版，看到整体界面，预留稳定接口，各自的 AI 可继续改进。用户已要求直接推进该初版；本文记录实施默认选择，不将技术栈表述为用户指定。

## 范围与选型

采用 React/TypeScript + Vite + Express + Node 24 内置 SQLite。选择完整轻量本地应用而非纯静态图：可以实际验证权限和数据联动；相较 Spring Boot/MySQL，初次启动更少环境准备。HTTP API 不依赖具体数据库，后续可以替换为 Java/MySQL 后端。初版限定本机运行，不发布公共服务器。

12 功能见 task-list.md：xzh 用户认证/隐私资料/个人记录；csw 发布/浏览搜索/编辑撤回；stt 认领/站内沟通/规则匹配；gbl 审核/争议/备份恢复。功能实现不代表四位同学已完成课程贡献，也不代表已获教师验收。

校园身份为演示绑定，无法证明真实校园身份。注册普通用户，管理员只有种子账号。密码 scrypt，随机会话 token 仅后端鉴权。公开列表不泄漏学号和联系方式。匿名聊天隐藏真实身份但系统仍有参与人鉴权。站内消息采用刷新/轮询，不冒充已实现 WebSocket。匹配为类别、关键词、地点规则，不能自动确认认领。

## 行为

物品 type=lost/found；status=active/claimed/withdrawn；reviewStatus=pending/approved/rejected，三个维度独立。发布及编辑进入审核；管理员批准后公开。本人可看待审核记录。认领仅针对他人有效且审核通过的 found 信息。发布者批准/拒绝，申请人撤销待审申请或在批准后确认领取；完成一次后拒绝其他未决申请，物品归还。编辑/撤回不能破坏正在进行的认领。双方才能查看证明与消息。争议处理记录原因，不允许任意无约束改写终态。

## 页面

拾光广场（主页面：搜索、筛选、图卡、详情）、发布表单、我的认领（状态与消息）、个人中心（资料及发布）、管理工作台（审核、争议、备份）。首页可访客浏览，执行写操作引导登录。种子账号提供显式演示登录，不自动冒充登录。

## 视觉规范

校园布告栏式轻盈工具界面：浅雾灰 #F5F7F9、纯白 #FFFFFF、主墨色 #183335、校园绿 #136B58、淡绿 #E5F0E9、寻物橙 #B85C25。中文使用系统苹方/微软雅黑，正文 15–16px。左侧固定导航+宽敞的内容区，醒目的纸签式找回引导插画和图卡是视觉中心。插画用本地 SVG，图片可上传本地内嵌数据，不依赖外网素材。可见焦点、表单标签、失败反馈、空状态、移动端折叠菜单、对话框 Escape/焦点约束。

## 接口与交接

shared/types.ts 是数据契约，/api 使用 JSON，错误统一 {error:{code,message}}。模块文件按四位成员拆分；共享契约变更先对齐。文档提供任务清单（每功能两项质量要求）、API、ER/流程、交接指南。保留演示账号，生产化认证、上传存储、WebSocket 和外部匹配服务作为替换点。

## 验证与限制

验证认证、越权、发布搜索、认领状态机、参与人消息、审核、争议、备份恢复与输入验证；桌面及手机浏览器实际检查。备份包含内部数据库，仅管理员在本地使用。初版手动备份恢复，定时调度保留服务接口并列为后续工作。性能指标在实际测试记录前仅为目标。
