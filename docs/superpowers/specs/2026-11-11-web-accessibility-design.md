# 0.2.1 Windows 浏览器无障碍优化设计

## 目标与范围

用户已确认：保留现有 Web 技术栈，优化 Windows 浏览器无障碍体验，沿用四模块分类及现有文档格式，验证后提交并推送原 GitHub 仓库。依据本地《揭榜任务2-无障碍适配任务书.pdf》两页要求，只适配已有功能。

项目是 React Web 应用，并非原生 Windows 桌面工程。是否符合课程的平台口径待教师确认；不得声称已完成原生 UIA、真实读屏听读或系统高对比度实机验收。

## 方案比较

- **采用：现有 Web 版增量优化。** 保留 0.2.0 四模块、数据契约与视觉规范，补上现有审计未覆盖的错误关联和模态隔离；用户选择此方案。
- 原生 Windows 重写或套壳：扩大范围，不能仅靠套壳证明无障碍合规，本轮不采用。

## 改动

1. 公共 `AccessibleForm`：继续使用 HTML 原生约束，提交失败时生成可聚焦、可跳转到字段的错误汇总，以 `aria-invalid` 和 `aria-describedby` 关联错误；修正输入后清除过期错误。请求级失败仍由 `ErrorBox` 解释，不猜测出错字段。
2. 公共 `Modal`：只让最上层弹窗处理 Escape/Tab，下层弹窗与主页面不可交互；逐层关闭时恢复焦点，最后关闭后恢复原滚动状态。
3. 移动导航：打开时隔离主体，暴露模态名称/状态；关闭后恢复可访问性与焦点。图片上传说明在预览后继续存在，键盘焦点清晰可见。
4. 既有冒烟：等待最终可见状态，而不是在成功提示出现后立即读取旧 DOM。
5. 验证：新增使用隔离数据库、自启本地服务的浏览器回归，覆盖错误恢复、模态叠加、抽屉隔离和上传说明。沿用 axe/ARIA/截图格式，记录基线与新结果。

实施中根据审查补充：动态字段采用实例内稳定唯一 ID；受控值和字段集合变动后同步校验；抽屉跨桌面断点释放主体；四种错误态追加规则扫描并提高汇总文字对比度。这些均属于上述既有界面的适配边界。
